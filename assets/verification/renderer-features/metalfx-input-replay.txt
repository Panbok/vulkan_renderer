Reproducer

renderer path. It uses actual Metal4 command submission and Metal4FX, with no
Metal3 fallback. The source owns private inputs/output, staging/readback,
residency, scaler, compiler, queue, fence and command storage. Every submission
completes, including error feedback, before CPU upload or command-memory reuse.
Explicit fences order upload, scaler and readback. Run GPU commands serially.

Limits and cleanup
This is a controlled SDK input-sensitivity check, not a current-scene quality,
timing, native Vulkan, or API/shader-validation result. Captured source radiance
predates the latest SSR fade. Its separate checkpoints are not consecutive
simulation submissions; only the raster phase ordering is continuous. Repeating
them does not reproduce evolving SSR/GTAO, production heap aliasing or in-flight
overlap. No new 12-phase inputs are synthesized. Fixed exposure values 1 and 8
do not cover all possible exposure policies.
An initial utility run wrote all outputs, then crashed releasing a custom
feedback queue through its descriptor. Removing that borrowed custom queue and
using Metal's internally owned default fixed teardown; all controls above exit 0.
This was a diagnostic utility defect, not an observed MetalFX render failure.
The source snapshot remains retained for the ongoing MetalFX investigation.
No baseline was promoted. The five completed replay output directories listed
above were retired after their report digests and this record were checked.
The initial failed utility output was also retired after its cleanup defect was
diagnosed. The checked source, converter and comparison tool remain in the repo.
